# 60帧在30/60之间切换：运行核查

2026-10-12用户反馈：新动画镜像将提供给其他测试者；60帧有时回到30，有时在30/60之间切换。具体场景与同步VPS/速度数据尚未收到，不将静态补丁证明当作稳定60帧验收。

## 本轮实证

- 修复镜像的SCKA_200.43重新读取SHA256为35cc6048f0e1f68d06bf3e515b99de3263e5092be62d6215cff5e74aa0ea15f0，帧等待指令仍为28410002。动画修复没有把60帧写入ISO。
- 最近emulog记录已加载60帧条目，但日志没有这次30/60切换时的连续FPS/VPS/模拟速度观测。
- 当前已安装PNACH的60帧部分由000C3FE0全局SELECT开关控制：值1写28410001，值0写回28410002。勾选条目与运行时开关状态不同，不能仅凭“已加载”宣称持续生效。尚未取得切换时该变量的内存值，不据此断言它是故障原因。
- 当前配置EE Cycle Rate/Skip均0，3倍分辨率。最近日志显示指定RTX4070 Laptop GPU未找到，实际回退AMD Radeon780M；这是真实适配器记录，不是性能根因证明。
- 新镜像、PNACH、模拟器设置与存档在本轮未改动。

## 下一次观察

记录掉到30帧时的完整状态栏：FPS、VPS、速度百分比；说明是否同一普通操作场景来回切换，还是进入动画、菜单或战斗后变化。原SFD为约29.97fps，动画30fps不能单独作为60帧补丁故障信号。

先建立能捕捉实际问题的运行对照，再选择补丁开关、游戏内部帧等待、模拟器性能或帧率计数等调查路线。暂不盲改EE时钟、不把其他金手指一并开启，也不覆盖已通过用户动画复测的镜像。

FPS/VPS含义与性能计数截图要求参见[PCSX2官方性能诊断](https://pcsx2.net/docs/troubleshooting/performance/)。此前静态移植背景见[FRAME_LIMIT_PATCH.md](FRAME_LIMIT_PATCH.md)，当前SELECT分组规则见[HOTKEY_CHEATS.md](HOTKEY_CHEATS.md)。
